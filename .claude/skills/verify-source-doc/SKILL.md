# 核对上游源实现与其接口文档的一致性

**一个源一份文档，以该源自己的文档为唯一依据。**禁止拿别的源的文档、别的源的代码、
或「同类协议的常见做法」当依据。核对范围严格限定在被点名的那个源，不要通读代码库。

## 第 1 步：定位这个源的文档与代码

| 要素 | 怎么找 |
|---|---|
| 文档 | `docs/` 下该源的 PDF/DOCX/MD/XLSX。用户给了就用用户给的 |
| 客户端 | `internal/infrastructure/upstream/<kind>.go` |
| 装配 | `cmd/relay/main.go` 的 `buildClient` case + `labelFor` |
| 配置 | `config.example.yaml` **和**实际部署的 `config.aliyun.prod.yaml` 等 |
| 契约映射 | 聚合路由才有，如 `internal/infrastructure/upstream/swfpcontract.go` |

`.docx` 用 PowerShell 解 zip 读 `word/document.xml`（正文段落 + 表格都要取，字段表
都在表格里）；`.pdf` 用 Read 工具**整篇读完**，别 grep 片段——鉴权/示例代码常在文末。

## 第 2 步：逐条核对（每条都要给出结论，不许跳过）

1. **接口清单**：文档「接口协议」章节的**每一个**业务接口，逐个标注「已实现 / 未实现」。
   未实现的必须在代码注释里写明理由，否则算缺陷。
2. **地址与路径**：生产/测试两套地址；路径拼接方式（如 `…/api/ws/<业务接口>`）；
   HTTP 方法、`Content-Type`、编码。
3. **报文信封**：外层/内层结构、字段名与大小写**逐字**对（`AppID`、`ReqData`、
   `StartIndex`、`CountLimit`…），含上游自带的拼写错误（如 `monthlyInvoiceSummryInfo`
   少个 a）——原样照抄，不许"纠正"。
4. **加密/签名**：算法、分组模式、填充、IV、编码。
   **凭证编码形态必须验算**：AES 密钥只接受 16/24/32 字节；64 个十六进制字符
   = 32 字节 AES-256（要 hex 解码），不是 64 字节 ASCII；Base64 的要先解码。
   **拿真实凭证在本地跑一遍加密**，算不出密文的就是硬缺陷。
5. **请求参数**：每个字段的名字/类型/长度/必填性/默认值/取值范围（如分页
   `CountLimit` 1~1000 默认 1000），与网关校验器口径是否一致。
6. **应答字段**：白名单、缺失补空、类型归一；契约映射表逐行核对语义口径。
7. **结果码**：文档结果码表每个码都要有归一化去处（查得/查无/上游侧错误），
   含「其余按此顺序拓展」这类开放式约定。
8. **文档自相矛盾**：报文示例与字段表拼写不一致时（`invoiceDayMonth` vs
   `invoceDayMonth`、`buyerTaxpayerIdNum` vs `buyerTaxPayerIdNum`）**两种都兼容**，
   并在代码注释里记下矛盾出处，不要挑一个赌。
9. **真实配置已装配**：打开实际部署的配置，确认该源**确实在**
   `versions.<route>.upstreams` 列表里、凭证是真值而非 `REPLACE_WITH_…`。
   `go build` 通过 ≠ 线上调得通——废弃写法（单块 `upstream:` + `products:` 数组）
   会让整条路由静默退化，这是"代码没问题但线上调不通"的头号原因。

## 第 3 步：分清「代码错」与「环境错」

用户报"调不通"时先定位在哪一层，不要一上来改协议：

| 现象 | 多半是 |
|---|---|
| `crypto/aes: invalid key size N` / 本地就加密失败 | **代码错**：凭证编码形态搞错 |
| `curl: (52) Empty reply from server`、连上即断 | **环境错**：上游按源 IP 白名单，需把部署机出口 IP 报给上游加白 |
| 上游返回业务错误码 + 明确字段名 | **代码错**，且**以服务器报错为准**改字段名（比文档示例权威） |
| 路由整体无响应/子源缺失 | **配置错**：该源没装配进 `upstreams` |

本机在代理（如 Mihomo fake-ip）后面时，`Test-NetConnection` 的 `TcpTestSucceeded:
True` 是假信号——它连的是本地代理，不代表真能到上游。真实连通性必须**从部署机复测**。

## 第 4 步：输出与修复

先给一张「不一致清单」表（文档要求 / 代码现状 / 严重性），再动手改。修复要求：

- 密钥/签名一类推导逻辑**显式实现 + 单元测试**，非法输入立刻报错，禁止静默降级；
- 不改判定表与计费口径（除非用户要求）；
- 改完跑 `go build ./...`、`go vet ./internal/... ./cmd/...`、
  `go test ./internal/...`；
- 涉及计费/接口范围的改动（如补实现一个文档里有但此前没接的接口，会不会多计费）
  **先问用户再动**。
